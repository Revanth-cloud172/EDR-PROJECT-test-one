# STM32 EDR Security Simulation — GitHub Pages Website

A static, browser-based educational simulation for a tamper-aware automotive Event Data Recorder. No backend, server, paid service, or physical hardware is required. The site is designed for GitHub Pages.

## Features

1. **Vehicle telemetry simulation:** simulated speed, longitudinal acceleration, yaw rate, chart and rolling sample buffer.
2. **Event recording:** trigger a simulated impact, preserve pre-event samples, capture a post-event window, and freeze the incident into a hash-chained evidence record.
3. **Cryptographic tamper demonstration:** SHA-256 evidence hash chain, integrity verification, intentional local payload tampering, and restore-from-in-memory-demo-copy.
4. **Forensic dashboard:** incident register, activity log, evidence-chain inspector, analyst notes and JSON forensic bundle export.
5. **Suggested cryptographic key:** browser-generated ECDSA P-256 key pair, public JWK display, and challenge sign/verify demonstration using Web Crypto.

## Run locally

Because Web Crypto requires a secure context, use `localhost` rather than opening the HTML file directly:

```bash
python -m http.server 8000
```

Then open `http://localhost:8000`.

## Deploy to GitHub Pages

1. Create an empty repository on GitHub (for example, `stm32-edr-forensic-simulator`).
2. Extract this ZIP and open a terminal in the extracted folder.
3. Run:

   ```bash
   git init
   git add .
   git commit -m "Add STM32 EDR forensic simulation"
   git branch -M main
   git remote add origin https://github.com/YOUR_USERNAME/stm32-edr-forensic-simulator.git
   git push -u origin main
   ```

   Replace `YOUR_USERNAME` with your GitHub username and adjust the repository name if needed.
4. On GitHub, open **Settings → Pages**. Set the build/deployment source to **GitHub Actions**.
5. The included `.github/workflows/pages.yml` workflow will deploy on pushes to `main`. Check the **Actions** tab for the deployment status. The site URL will normally be `https://YOUR_USERNAME.github.io/stm32-edr-forensic-simulator/`.

## How to demonstrate it

1. Start telemetry, or use **Add sample** to populate the buffer.
2. Trigger a simulated crash. Select impact severity and pre-event window.
3. Open **Cryptographic security** and click **Verify evidence chain**.
4. Click **Simulate tampering**, then verify again. The modified record should fail hash verification.
5. Generate the demo ECDSA key pair, then click **Sign & verify challenge**.
6. Open **Forensic evidence**, add analyst notes, and export the JSON bundle.

## Security and engineering limitations

- This is a demonstration, not a validated automotive EDR or secure evidence appliance.
- Telemetry is generated by JavaScript and is not sourced from an STM32, ESP32, IMU, or a vehicle.
- The hash chain is stored in browser memory. A real attacker who can replace the full chain can recompute hashes; hashes alone do not prevent deletion or prove origin.
- The “restore demo copy” button restores an in-memory clean snapshot for demonstration. It is not real forensic recovery.
- The ECDSA private key is generated as non-extractable in the current browser session. It is not persisted; refreshing the page loses it. The public JWK is exportable.
- This static GitHub Pages app has no authentication, central database, server-side timestamps, or trusted hardware attestation.
- A production design needs a threat model, secure boot, authenticated enrollment, device proof-of-possession, protected monotonic counters, secure storage, verified attestation, access controls, audit logs, and an external trust anchor.
